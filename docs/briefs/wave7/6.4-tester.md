WHAT THE TABLE IS (so you can test it)
 Feature Lab is a showcase table, the 6.4 subphase of Kilohertz Pinball. It exercises: a Banana flipper (curved bat) opposite a straight flipper; a backbox mini-playfield (collision layer 4) with ONE vertical flipper, fed by a VUK from the main playfield; an open lower area cleared for the 79.4 mm `jumbo_xl_resin` ball (declared with `[balls] restrict` = layer 0 plus a plan-view area polygon, validated by the 2.8 clearance validator); a holding magnet fed by a dispenser that serves `standard_steel` or `low_rem_steel` (remanence 0.05 versus 0); and a Glo-Ball (`uv_globall`) whose Magnus force comes from `[physics] globall_magnus_coeff` (bounds 0 to 5e-5, default 1e-5).
 Engine facts you can rely on: `pin_app::orchestrator::load_validated(&Path, SimConfig) -> Result<Simulation, String>` (pin_assets::load_table, the clearance validator for every declared ball, then Simulation::load); `pin_assets::load_table` for structure; the Simulation test API (`set_switch`, `release_switch`, `spawn_ball`, `spawn_ball_on_layer`, `set_ball_state`, `ball`, `ball_handles`, `advance`, `switch_hits(name)`, `score(player)`, `persist(key)`, `state_hash()`, `snapshot()`, `balls_in_play()`, `magnetisation(handle)`, `script_faulted()`, `script_queue_overflows()`), `pin_sim::replay` (records and replays an input stream to an identical state_hash), `pin_sim::alloc_guard`, and pin_sim's public autoplay API (see crates/pin_sim/tests/autoplay_*.rs for usage). Autoplay never presses `action` or `tilt`. Cabinet inputs are the switches numbered by `[cabinet_switches]`. There is no host command to remove a ball.
