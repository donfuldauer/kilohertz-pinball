GOAL
  A deterministic, GPU-free `pin_sim::Simulation` that loads a table bundle, runs the fixed 1 kHz tick
  order with physics (balls, flippers, mechs, Magnus/remanence hooks), input staging and the rules
  script, exposes a test API for state injection and queries, and records/replays input streams to an
  identical state hash. It is what the grey-box (6.0), the autoplay bot (2.9) and the CI replay-hash
  job build on.

TICK ORDER inside step_1ms() (PLAN §2.2, fixed)
  1. Drain input events with timestamp ≤ tick time; update cabinet switch states.
  2. Deliver switch edges collected last tick to the script, then call on_tick.
  3. Apply HostCommandQueue (coils, magnets, lamps, spawns), then clear it.
  4. Step physics (CCD sub-steps inside the tick).
  5. Collect new switch edges and haptic events.
  6. Publish FrameStateSnapshot.

DELIVERABLES (PLAN 2.5)
  1. `Simulation` implementing the tick order above and `pin_core::sim::SimStep`.
  2. Test API: spawn a ball at a position and velocity, set switch states, advance N ticks, query ball and
     score state.
  3. Recorder and replayer: per-tick input events, RNG seed and table hash in a binary file;
     CLI flags `--record-inputs <file>` and `--replay-inputs <file>`.
  4. Fill the CI `replay-hash` job; add the allocation guard around `step_1ms()`.

CONTRACTS AND INTEGRATION OBLIGATIONS YOU MUST HONOUR
  Scripts
  * Build backends with `pin_script::load_backend_with(.., LuaConfig::engine(), WasmConfig::engine())`
    — 100 000 instructions and 2 MiB per callback (user-confirmed). Never `load_backend()` (1 M / 16 MiB).
  * Any thread that calls a Wasm backend needs ≥ `pin_script::wasm::MIN_HOST_STACK_BYTES` (2 MiB) of
    stack: tests and the CLI run the simulation on a spawned thread with that stack (document it on
    `Simulation`). A script fault ("tilt" state) never stalls the tick; it is surfaced as state.
  * The sim owns one seeded `Pcg32`; the seed is in the recording. Scripts own scoring; the host only
    stores what `scores` reports. Queue overflow drops the command and increments a counter (exposed).
  * `pairs()` order over table/function keys is not reproducible (DECISIONS "Orchestrator — 4.2
    pointer-keyed pairs order"): test scripts use integer/string keys.
  Input
  * `pin_input` router: clear the router `out` buffer before every `update` (3.1 review N1); call
    `advance` once per tick with non-decreasing ticks. Cabinet inputs are reserved switches from
    `[cabinet_switches]` (left_flipper, right_flipper, left_upper, right_upper, action, start, launch,
    tilt). Flipper buttons drive the flipper solver through the staging layer.
  Physics wiring (from the 2.2-S/2.3/2.4/2.7 integration notes)
  * Wiring order: flippers are moving-body set 0, mechs set 1 (`step_with_bodies`).
  * Build mechs with `MechSpec::from_def` (mm→m inside; `MechSi` has no parameters). Diverter, gate and
    newton_ball mechs are inert in `MechSet` and must be wired here: diverter → `StaticWorld::set_enabled`
    on its collider(s) driven by `HostCommandQueue::diverters`; gate as documented by 2.4;
    newton_ball → `NewtonChain`.
  * Magnus/remanence: `ball_ext::register_all(&mut solver)` once, after gravity is final (it captures
    gravity once; do not call `set_gravity` afterwards).
  * Static world from `playfield.glb` (z up, metres) collider nodes + `[[splines]]` guides/wireforms +
    transitions. Generated lane guides (`tablegen:` ids) carry no wall height: give guides the
    playfield `wall_height` (A.1) — log the decision.
  * Ball drain is detected by trough switches; a ball leaving the playfield bounds is removed.
  Out of scope (Subphase 6.0, do not build): audio/sound loading and the decoded-audio budget, haptics
  fan-out to `HapticsBus`/rumble/SSF, UDP telemetry, rendering, threads/timers of the real app. Step 5
  collects haptic events into a fixed-capacity per-tick buffer that 6.0 will drain (expose it).

VERIFICATION CRITERIA (PLAN 2.5, exact)
  1. A 10,000-tick recording replays to an identical state hash 10 times in a row (with balls moving,
     flippers firing from recorded inputs and a Lua script scoring).
  2. The allocation guard passes over 60,000 ticks with a script loaded (Lua; and Wasm if a Wasm
     fixture is available — pin_script has guest-sdk examples).
  Also (gate 5/6): `Recording::from_bytes` survives a bounded random-bytes proptest without panicking;
  the CLI round-trip (`--record-inputs` then `--replay-inputs`) prints the same hash.
  CI job `replay-hash` (ubuntu, windows, macos matrix): builds `pin_sim` in release, records a fixed
  fixture for 10 000 ticks, replays it 10 times, fails on any mismatch within one machine, and prints
  the hashes (and the 2.2-S seam digests, Wave 4 gate-fix N3) so cross-OS values are visible —
  cross-OS differences are reported, never failing (D9). Keep the fixture bundle small and in-repo
  (e.g. crates/pin_sim/tests/fixtures/), hand-written or produced by `pin_tablegen`.
