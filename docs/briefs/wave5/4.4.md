GOAL
  An in-game menu overlay (egui via egui-wgpu) with three panels — table browser, display setup and
  input setup — whose logic is a GPU-free, headless-testable state machine, with settings persisted in
  `config.toml`.

DELIVERABLES (PLAN 4.4)
  1. `egui-wgpu` overlay toggled by `Esc` or the controller Menu button.
  2. Table browser (preview art, metadata, feature badges, one-click load).
  3. Display panel (single vs. multi-monitor, PiP placement, camera presets, DMD vs. LCD).
  4. Input panel (profile, staging mode, live plunger and nudge calibration, debug wireframe toggle).

DESIGN CONSTRAINTS (Orchestrator)
  * Split: `pin_app::ui` holds the state machine (`MenuState`, actions, directory scan, config model)
    and no GPU code; `pin_render::ui` holds the egui-wgpu painter that draws a frame of the egui
    context onto a given surface view. The state machine is driven by plain events (`MenuInput`:
    toggle, navigate, select, back, text/slider changes) so tests never need SDL or a GPU.
  * Directory scanning runs on the I/O worker in the real app (only that thread touches the file
    system at runtime); the scanner is a plain function over a root path that returns entries sorted
    by a fixed key (deterministic). Broken bundles appear with their validation error, never panic.
  * Table switch lifecycle: Idle → LoadRequested(path) → Loading → Loaded | Failed(error) → Idle; a
    second request while Loading is queued or refused (document which). The menu emits a
    `UiCommand::LoadTable(path)`; the actual load is wired by 6.0 — expose the command stream and a
    method to report the outcome back.
  * `config.toml` persistence: a typed `AppConfig` (display mode, PiP placement, camera preset, score
    display DMD/LCD, input profile, staging mode, calibration values, wireframe toggle, last table)
    with `load(path)` / `save(path)`; unknown keys preserved or ignored (log choice); a corrupt file
    falls back to defaults with a reported warning; save is atomic (write temp + rename).
  * When the Menu is open, cabinet inputs map to menu navigation and are not forwarded to the sim.
  * 3.2 review N5: `ProfileMapper` is last-writer-wins per cabinet input; wiring the mapper into the
    platform layer is 6.0's, but the input panel's live display must OR the sources per input.

VERIFICATION CRITERIA (PLAN 4.4)
  Headless UI state-machine test for directory scanning, table switch lifecycle and `config.toml`
  persistence. Plus (gate 5): the config parser survives a bounded random-bytes proptest. Plus a
  `gpu-tests` smoke test in pin_render that paints the overlay to an offscreen target on lavapipe and
  asserts analytically that the menu region differs from the background and the rest is untouched.

VISUAL CHECKLIST
  The overlay is legible over a bright playfield (semi-opaque backdrop), scales with display DPI, and
  shows the three panels with their controls; feature badges are visible in the browser list.
