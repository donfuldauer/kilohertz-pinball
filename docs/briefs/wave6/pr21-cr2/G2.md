CONTEXT
 * input_router.rs ~213-224 `queue_neutral_axes(&mut self, device: u32, analog: &[Option<(CabinetAxis, f32)>; AXES])`: for each (cab, _) driven by the leaving pad it checks `driven_elsewhere` (any other pad with an analog slot mapped to `cab`) and, if so, queues nothing; else queues `Pending::Axis(cab)`. `flush_pending` (~228-243) emits `InputEvent::axis(ts_ns, axis, 0.0)` for Pending::Axis and a button release for Pending::Button. `Pad.analog: [Option<(CabinetAxis, f32)>; AXES]` holds each pad's last mapped value per axis slot. `remove_gamepad` (~246+) and the profile-replacement path call `queue_neutral_axes`. `InputIngest` retains the latest axis event, so emitting nothing leaves the departed pad's value live.
 * Failing scenario (CodeRabbit comment 4577152677, thread PRRT_kwDOVrUJEc63mhvK, VALID): pad 2 sends LeftTrigger=8192, then pad 1 sends LeftTrigger=i16::MAX; pad 1 disconnects; the code finds pad 2's stored value and emits nothing, so the cabinet stays at pad 1's full travel. Replacing pad 1's profile has the same result.
 * input_router_fixes.rs ~190-216 test `nudge_axis_state_is_per_pad` (nitpick in the CodeRabbit review body, VALID: "let pad 1's nudge expire before pad 2's first high sample, keep pad 1 above threshold, and require a negative NudgeX event from pad 2"). The current test lets pad 2 cross while pad 1 is above threshold but does not require an emitted event from pad 2, so shared latch state would still pass.
