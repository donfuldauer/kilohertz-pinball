GOAL
  Stand in for human playtesting: a seeded heuristic bot that plays any table through the public `Simulation` API, and a soak runner that plays N seeded games per table headless, faster than real time and in parallel, then reports mechanical soundness and coverage as JSON and Markdown. It proves a table is mechanically sound and fully reachable; it does not judge feel.

REQUIREMENTS / DELIVERABLES
  1. `pub enum SkillLevel { Novice, Standard, Expert }` and `pub struct Bot` (`Bot::new(seed: u64, skill: SkillLevel) -> Bot`; `fn tick(&mut self, sim: &mut Simulation)` called once per tick BEFORE `sim.advance(1)`; deterministic for a given (seed, skill, table): the same inputs give an identical `state_hash` sequence). Behaviour: starts the game (`start`), plunges (`launch`, hold time chosen by the seeded PCG), flips when a ball is PREDICTED to cross a flipper's sweep (predict from ball position/velocity and flipper pivot/angles from the snapshot and `flipper_set()`; no named-table special cases, rule 6), holds the flipper to cradle a ball when slow and near the bat, nudges occasionally (action/tilt avoided except a bounded nudge rate that cannot tilt in a normal game; configurable). Skill levels differ ONLY by reaction jitter (ticks of delay, PCG-drawn) and miss rate (probability of skipping a predicted flip): e.g. Novice 40 ms jitter / 30% miss, Standard 15 ms / 10%, Expert 3 ms / 1%; expose `SkillParams` and document the defaults.
  2. `pub struct SoakConfig { games: u32, seed: u64, skill: SkillLevel, threads: usize, max_game_ticks: u64, ... }` and `pub fn run_soak(bundle: &Path, cfg: &SoakConfig) -> Result<SoakReport, SimError>`: N games, game i uses seed derived from `cfg.seed` and `i` with a fixed hash (not iteration-order dependent), run with std threads (no new dependency); each game headless on simulated time (D8, never sleeps, never reads wall clock for logic). The report is identical for any `threads` value (results are merged in game order). Wall-clock tick timing is measured separately for the tick-time budget and excluded from determinism comparisons (put it in a clearly separate `timing` section; the budget check can be disabled via config for tests).
  3. Health checks, each producing a named `Finding { kind: FindingKind, subject: String, game: u32, tick: u64, detail: String }` (subject names the exact switch / shot / mode / ball / mech or a coordinate):
       StuckBall: ball speed below 1 cm/s for more than 10 s of simulated time outside a trough, lock or held cradle (a held flipper cradle with the flipper held and the ball on the bat is NOT stuck; define exemptions from table data: trough/lock/scoop switches closed, flipper held, magnet holding, plunger lane at rest), subject = position and the nearest named feature.
       EscapedBall: ball outside table bounds (playfield extent from the loaded table's collider bounds plus a margin, and below the floor).
       NonFinite: NaN/Inf in any ball, flipper or score.
       UnreachableSwitch / SwitchCoverage: every declared switch (excluding cabinet inputs) must be hit at least once across the soak (reported as the list of never-hit switch names, plus per-switch hit counts).
       ShotCoverage: for each `[[shots]]`, its `sequence` of switches observed in order within `window_ms` at least once (report per shot count).
       ModeCoverage: each `[[modes]]` entry observed started at least once (detect via the `display_scenes` command `start_scene` or via a counter exposed by the public API; if not exposed, record the gap and report a request).
       ScriptError (script_faulted / script_error / fault count), QueueOverflow (`script_queue_overflows()` > 0 or `counters()`), TickBudget (99.9th percentile of measured tick time above a configured limit, default 0.35 ms).
       Distributions: ball time (ticks/ms per ball) and per-game score: count, min, median, p90, p99, max.
  4. Reports: `SoakReport::to_json() -> String` (stable key order, versioned `"schema": 1`) and `to_markdown() -> String` (summary table, findings grouped by kind with subject names, coverage tables, distributions). Also `pin_sim soak <bundle> --games N --seed S --skill novice|standard|expert --threads T --out <dir>` writing `soak_report.json` and `soak_report.md` and exiting with code 1 when any finding of kind StuckBall, EscapedBall, NonFinite, ScriptError, QueueOverflow exists, or the coverage is incomplete (the coverage failure policy is documented), 0 otherwise, 2 for bad arguments.
  5. Fixture tables with PLANTED DEFECTS under tests/fixtures/autoplay/ (small hand-authored bundles built with the same loaders; keep them tiny): (a) a ball trap (a pocket a ball can enter and never leave outside any trough) -> StuckBall naming it; (b) a gap in a wall (ball escapes) -> EscapedBall; (c) an unreachable switch (declared, hidden behind geometry) -> UnreachableSwitch naming exactly that switch; (d) a Lua script that errors on exactly one mode -> ScriptError naming the mode/entry, plus a mode never started -> ModeCoverage; (e) a clean fixture that passes with zero findings (and with `[[shots]]`/`[[modes]]` fully covered). Each planted defect is caught and NAMED in both the report and the CLI output.
  6. Determinism: a given seed gives byte-identical reports (excluding the `timing` section) and an identical per-game `state_hash` list across 3 runs and across thread counts 1, 2, 4.
