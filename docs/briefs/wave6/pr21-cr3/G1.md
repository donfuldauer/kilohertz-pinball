GOAL: On the table path the render thread must never acquire (get_current_texture) or present a blocking-mode surface for a Score/Backglass window. Today a backglass/score surface that offers only Fifo (SurfacePlan::Secondary) is acquired and presented from the render thread every 4th loop iteration, so its vsync-bound acquire can stall the playfield and a stalled acquire prevents the render-thread join. Such a surface must instead be deferred: not drawn on the table path, with one stderr note, while the playfield, the table renderer and all scene/score display commands continue to work.

DECISION ALREADY TAKEN (by the classifier, record it; do not re-open it)
Options considered: (a) a real presenter-thread hand-off (render the table texture on the render thread, copy it to a pin_app-owned thread that owns the wgpu::Surface); (b) defer FIFO-only secondary surfaces; (c) keep that surface on a separate pin_render SurfaceSet presenter. Chosen: (b), with (a) queued as a follow-up.
 * (a) is technically possible inside pin_app (wgpu::Surface, Device and Queue are Send + Sync on native; surfaces would be configured with COPY_DST, or need a blit pass when the surface capabilities lack it) but it is a new threaded subsystem with window-lifetime, resize, device-lost and join-timeout semantics that no CI job can exercise (the CI adapters Metal, WARP and lavapipe do not produce a FIFO-only secondary surface), so it cannot be shipped safely in a review round.
 * (c) is rejected: a second SurfaceSet only draws debug lines, so the secondary window would show the wrong content.
 * (b) is the smallest change that makes the D19 rule hold ("The playfield paces presentation, while secondary surfaces use supported non-blocking modes or their own presenter threads when only FIFO is available"): the render thread only ever draws the playfield (which paces, by design) and secondary surfaces that offer a non-blocking mode.
