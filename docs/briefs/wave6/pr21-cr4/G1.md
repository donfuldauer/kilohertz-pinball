DESIGN (binding on behaviour; the file split and names are yours):
A. Plans. Replace `SurfacePlan::Deferred(mode)` by `SurfacePlan::Presenter(mode)` (and `SlotDecision::Defer` by `SlotDecision::Present(mode, format)`): a backglass/score surface with a blocking chosen mode gets a presenter thread. With `opts.force_presenter_thread` a backglass/score surface ALWAYS gets the presenter path, also when it offers Mailbox (then configure its surface with the mode `choose_present_mode` picked; the test must still pass whatever the adapter offers). The playfield is never Presenter. `table_set_accepted`: still needs a Direct surface and no Unsupported playfield; Presenter surfaces never reject the set. `Skip` (no 8-bit format) and `Reject` stay.
B. Slot kinds. A slot is either Direct (as today) or Threaded. A Threaded slot keeps `renderer`, `routes`, `planned`, `pixel_size`, `minimized` on the render thread, so `apply_display_command` reaches its renderer exactly like a Direct slot's (every routed display command must reach the renderer of every retained slot; add a test that proves it for a Threaded slot). The Threaded slot additionally owns a small pool of offscreen textures (same format as the surface, size = surface pixel size, usage RENDER_ATTACHMENT | COPY_SRC | TEXTURE_BINDING) and a handle to its presenter thread. The `wgpu::Surface` and the `WindowGuard` move into the presenter thread (via `spawn_guarded`, so the surface drops before the guard, also for a detached thread).
C. Hand-off (pure and unit-testable, no GPU types in its core logic: make it generic over the frame payload). A latest-frame mailbox with a free-slot pool of N = 3 frame slots: the render thread takes a free slot (non-blocking, `try`/`Mutex` held only for a few instructions, never across a GPU call, never a condvar wait), renders into it, submits, then posts it to the mailbox; if the mailbox already holds an unconsumed frame, that older frame is returned to the free pool (latest wins) and counted as `dropped`; if no slot is free (presenter holds one, one in the mailbox, one being rendered is impossible with N=3, but handle it) the render thread skips this surface this iteration and the status is `SurfaceStatus::Busy`. The presenter thread waits on a Condvar (or channel) for a posted frame or a shutdown/closed flag, takes the latest, does its blocking work, then returns the slot to the pool. A frame is only presented after the render thread's submit for it was made on the same queue (queue submission order guarantees the copy sees finished rendering; no CPU wait). Resize: the post carries the pixel size; on a size change the presenter reconfigures the surface (and the render thread recreates the offscreen pool, discarding stale slots whose size differs; a stale-size frame is dropped, never copied). Counters (shared atomics): posted, presented, dropped_latest, busy_skips, configure_failures.
D. Presenter thread body: on a job, reconfigure when the size changed or a previous configure failed (use `configure` with its error scope; configure calls on the presenter thread and the render thread's own submits/configures on the same device are serialised through one `Arc<Mutex<()>>` gpu lock that both sides take around `queue.submit` and `surface.configure`, as pin_render does; take it only around those calls, never around `get_current_texture`/`present`). Acquire with `get_current_texture`: Success/Suboptimal -> copy; Outdated/Lost -> reconfigure, drop the frame; Occluded/Timeout/other -> drop the frame (count it) and keep running. Copy: if the surface's capabilities (`surface.get_capabilities(adapter).usages`) include COPY_DST, configure with `RENDER_ATTACHMENT | COPY_DST` and use `copy_texture_to_texture` (equal formats and extents); otherwise blit with your own small fullscreen-triangle render pass (WGSL, sampler + texture binding, written in pin_app). Use the blit path whenever COPY_DST is missing; do not defer for lack of COPY_DST. Then `queue.submit`, `queue.present(frame)`, `presented += 1`. A panic in the presenter thread must not take down the render thread (the mailbox closes; the render thread sees `closed` and marks the slot dead: it stops rendering it and prints one stderr note; display commands to it are then ignored).
E. render(): for a Threaded slot return `Hidden` when minimized or zero-sized (same rule as Direct), `Busy` when no free slot, otherwise render into the free slot (clear for non-playfield, then `renderer.encode(...)` with the slot's texture view exactly like `render_slot` does with the frame view), submit, post, and return `Presented` (it means handed off). `frames` counts hand-offs for Threaded slots like presents for Direct. `frame_paced` must remain true only for a presented Playfield (a Threaded slot never paces). The render thread must never call `get_current_texture` or `present` on a Threaded slot's surface (it no longer owns it).
F. handle_window_event for a Threaded slot: PixelSizeChanged updates `pixel_size`, `routes`, resizes `renderer` and rebuilds the offscreen pool on the render thread, and lets the presenter reconfigure on the next post (do not call `Surface::configure` on the render thread for a Threaded slot's surface; you do not hold it). Minimized/Restored etc. as for Direct.
G. Shutdown (Drop of the Threaded slot / AppSurfaces): close the mailbox (sets closed, notifies the condvar), then join with the bounded timeout `PRESENTER_JOIN_TIMEOUT` using your own `join_with_timeout` (poll `JoinHandle::is_finished` every 1 ms, render side only); on timeout print one stderr note ("presenter thread did not stop within ..., detaching it") and detach; the detached thread still owns the surface and its WindowGuard, which keeps the window alive (SDL windows are destroyed on the main thread only after the last guard drops; main.rs waits `wait_all_released` and exits without teardown if a presenter is stuck). Dropping all presenters must be done before the Direct slots' surfaces are dropped only as far as drop order of fields allows; do not hold any lock while joining. A presenter that is blocked inside a Fifo acquire must not be able to block the render thread's shutdown beyond the timeout, and the render thread must never block on a FIFO surface at any time.
